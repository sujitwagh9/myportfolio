## Problem

As the platform spread to more businesses, each deployment needed different settings: service-specific configuration, which services to run, and whether Azure AD sign-in was required. Maintaining separate configuration files by hand for services like Apache Superset and Apache NiFi became complex and error-prone.

## Design

We designed and built a **Config Manager**, a system that generates configuration dynamically:

- It takes deployment inputs such as **company name, SSL certificates, required services and authentication preferences**.
- It fills those values into standard templates and the relevant files, and **turns features like Azure AD on or off** depending on the inputs.
- It handles sensitive parameters such as client credentials automatically, so they aren't edited by hand.
